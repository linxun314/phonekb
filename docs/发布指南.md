# 开源发布指南（GitHub）

仓库已经整理好（git 已初始化并完成首次提交），剩下的是把它推到 GitHub 并发布 APK。
以下命令在仓库根目录 C:\Users\22453\Desktop\phoneKB 执行。

## 1. 创建 GitHub 仓库

1. 登录 GitHub → 右上角 **+** → **New repository**；
2. 仓库名建议 `phonekb`（或 `PhoneKB`），描述例如 "把 Android 手机变成蓝牙键盘/触控板/遥控器，平板零安装"；
3. **不要**勾选 Add a README / .gitignore / license（本仓库已有）；
4. 创建后记下仓库地址，例如 `https://github.com/你的用户名/phonekb.git`。

## 2. 推送到 GitHub

```powershell
cd C:\Users\22453\Desktop\phoneKB
git remote add origin https://github.com/你的用户名/phonekb.git
git push -u origin main
```

> 首次 push 会让浏览器登录 GitHub 授权；也可以在 GitHub 设置里创建 Personal Access Token 作为密码。
> 如果仓库名想用别的，把 URL 换掉即可。

推送成功后，仓库首页应能看到 README、截图、docs、源码与 `.github/workflows/build.yml`。
打开 **Actions** 标签页可以看到自动构建的 debug APK 产物（Artifacts），也可以手动 **Run workflow**。

## 3. 构建可发布的 APK

任选一种：

```powershell
# 方式一：项目自带脚本（不装 Android Studio）
powershell -ExecutionPolicy Bypass -File tools/build.ps1 -Clean -VersionName 0.12.1 -VersionCode 17
# 产物：build\PhoneKB.apk

# 方式二：Gradle
.\gradlew assembleDebug
# 产物：app\build\outputs\apk\debug\app-debug.apk
```

验证 APK（可选）：

```powershell
adb install -r build\PhoneKB.apk
```

## 4. 发布 GitHub Release

1. 仓库页 → 右侧 **Releases** → **Create a new release**；
2. Tag 填 `v0.12.1`，Target 选 main，Release title 例如 `v0.12.1`；
3. 描述可以从 [CHANGELOG.md](../CHANGELOG.md) 复制；
4. 把 `build\PhoneKB.apk` 重命名为 `PhoneKB-0.12.1.apk` 后拖进 Assets 上传；
5. 点击 **Publish release**。

这样别人就能在 Releases 页直接下载安装。

## 5. 以后更新版本的流程

1. 修改代码；
2. 改版本号（三处保持一致）：
   - `app/src/main/AndroidManifest.xml` 的 `versionCode` / `versionName`
   - `app/build.gradle` 的 `versionCode` / `versionName`
   - `tools/build.ps1` 的默认参数
3. 更新 `CHANGELOG.md`；
4. 构建 + 真机验证；
5. `git add -A && git commit -m "vX.Y.Z: 说明" && git push`；
6. 按第 4 步建新的 tag / release。

## 6. 关于签名

- 当前 APK 使用仓库 `keys/debug.keystore`（debug 签名，已 gitignore，不会进仓库）签名，可以正常安装到手机，适合自用/测试分发。
- 如果你希望这个 APK 长期可升级（同一个 keystore 才能覆盖安装），**请备份好签名文件**，不要弄丢。
- 如果要上应用商店或长期正式分发，建议生成 release keystore：

```powershell
keytool -genkeypair -v -keystore keys\release.keystore -alias phonekb -keyalg RSA -keysize 2048 -validity 10000
```

  然后修改 `tools/build.ps1` 里的 keystore/alias 参数为 release 文件，构建后先用 `apksigner verify -v` 验证再发布。

## 7. 注意

- 不要提交 `keys/`、`local.properties`、`_local/`（里面是参考 APK 反编译材料，含 GPL 代码，不能进仓库）；`.gitignore` 已排除。
- 如果希望以后由 AI 代劳 push，需要先在本机完成 GitHub 登录（agent 无法代你完成网页登录/授权）。
