# 设计原则（UI / 人体工学）

> 这份文档记录 PhoneKB 的界面为什么这么做，改版时照它判断，不要凭「看起来好看」。

## 一、人体工学优先
1. **常用键必须在拇指弧内**：手机横握时，拇指能舒服扫到的只有左右下角各约 1/4 屏。方向盘、ABXY、摇杆放这里；肩键只放食指位（顶边两角附近），不塞到拇指够不到的地方。
2. **顶部与底部留安全带**：手机有系统手势条和圆角，按钮距边缘至少 8–12dp；肩键带、键簇带、摇杆带之间也要留 6–14dp，任何两组的**命中矩形不允许相交**。
3. **同族键尺寸一致**：ABXY 四键等径，L1/R1、LT/RT、SELECT/START 各自等高；不允许为凑位置把某一个键压扁。
4. **有效触控 ≥ 48dp**：小于这个尺寸的键只做「辅助提示」，不作为主操作目标（例如摇杆刻度、扇区小点）。
5. **命中区 ≥ 视觉区**：摇杆命中区是可视圆的 1.55 倍；按键命中区外扩 6dp；圆盘中心 25% 半径视为中立，避免手指轻放就误判方向。

## 二、缩放与布局
1. **尺寸由屏幕空间反推，不靠猜**：先算可用高度/宽度，再取最大半径，最后乘用户滑块。滑块只缩放键本身，不改变「带」的位置，因此放大不会挤掉别的键。
2. **分方向钳制**：横屏键簇贴左右边、摇杆夹在中间；竖屏两簇并排时宽度 = 4×半径，是硬上限。同一个公式套两个方向必然重叠（v0.29.1 的 bug 就是这么来的）。
3. **竖排是竖屏唯一能放大的方向**：竖屏要「大键」，必须把两组键上下排（大键模式的做法），而不是继续加宽。
4. **如实告知**：滑块给的是「希望值」，界面显示「本屏实际 N%」。宁可承认放不下，也不让用户拖了没反应。
5. **横竖屏分别验收**：每个布局改动都要拍 100% / 200% / 大键模式 × 横 / 竖共 6 张图，确认无重叠、无越界、无遮挡。

## 三、反馈与体感
1. **按下先发数据，再管视觉**：发送 → 重绘 → 震动，顺序不能反；震动与重绘都不能挡在发送前面。
2. **触感要有下限**：轻点也要保证按住 ≥ 34ms，否则主机会把按下+松开当成抖动丢掉。
3. **视觉反馈要滞后于功能**：极速模式下宁可不画摇杆、不震动，也要保按键跟手。
4. **状态要能一眼看出**：连接状态（绿点 / 已连接 · 设备名）、当前按下键高亮、摇杆当前方向、圆盘当前扇区，都必须即时可见。

## 四、设置与可恢复
1. **每个开关都能关掉**：大键模式、极速模式、震动、触控点击、方向修正、灵敏度都能回到默认；设置里有「重置」清布局偏移。
2. **改动可撤销**：弹窗「取消」必须还原到打开前的状态（包含布局、类型、两个尺寸、大键模式）。
3. **横竖屏各存一套**：屏幕形状变了，人手的可达区域也变了，不能共用一份偏移。
4. **旧数据不能把人坑死**：布局偏移带方向/布局前缀，改版换前缀让旧数据自然失效，而不是让用户自己找残留。

## 五、文字与排错
1. **排错信息写进帮助**：「方向键偏一格」「摇杆没反应」「按键被裁」都在帮助弹窗与设置里给出具体操作，而不是只在 Release 说明里。
2. **文案用动作词**（拖动 / 缩放 / 按住滑动），不用抽象名词。
3. **设置项标签写清范围**（如「按键大小（ABXY / 肩键 / 菜单键）」），避免用户误会调的是区域宽度。
